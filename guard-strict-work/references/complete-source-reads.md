# Complete source reads

Use this guidance when the user requires whole-file source reads or a disputed ownership or lifecycle conclusion depends on context beyond a located symbol. Preserve the current source-access and task boundaries.

## Select files by the decision

- Use `rg` for navigation before or after complete reads. Search can identify the selected owner set; excerpts cannot replace the required full bodies when closing the dependent conclusion.
- Select the producer, model, consumer, public interface, and protecting tests whose complete contents can change that conclusion. An explicit whole-file requirement does not imply reading an entire directory or repository.
- Complete those selected files through EOF before making the dependent ownership or lifecycle conclusion. Continue independent authorized work whose evidence requirements are already satisfied.

## Read and attribute the selected contents

Batch metadata for the selected set and use bounded, non-overlapping line ranges compatible with the consuming reader. A successful metadata plan establishes planned ranges, not that their bodies were read.

Read one file and one range per result. Keep each path, hash, final logical line, next unread line, and completion state in existing task context. Advance only through visibly complete output; after truncation, resume at the first unconfirmed line without restarting completed ranges or siblings.

An empty file has no body ranges: its zero-byte snapshot establishes completion for that input. For nonempty files, mark completion only after the selected body has been read through EOF.

## Reuse applicable evidence

Reuse completed reads of unchanged source files. A prior EOF read combined with an exact, narrow owned edit can establish current contents without another whole-file read. Reconcile affected evidence when concurrent drift, a broad rewrite, or other changes invalidate that basis; preserve unaffected files and ranges.

After context loss, a hash and completion marker do not reconstruct the source body. Read the detail needed for the current decision when it is no longer available. Source-evidence reuse does not override `$resume-strict-context` requirements to reload the active goal and applicable procedural skills.

When the user strengthens the reading requirement during work, preserve applicable evidence, complete the newly required reads, and pause only conclusions that depend on missing evidence.

## Keep recording proportional

Report completed files, incomplete ranges, and affected evidence in the existing response or task record. Do not create a separate persisted audit unless the user-requested deliverable or an already-authorized workflow intrinsically requires it. Reading classification and bookkeeping grant no additional execution, persistence, Git, delegation, or cross-repository authority.
