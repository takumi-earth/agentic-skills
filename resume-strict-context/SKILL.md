# Resume Strict Context

Recover lost authority before task effects. Summaries locate evidence; they do not replace the designated contract.

## Distinguish recovery from continuation

Actual context replacement, a fresh worker/session without the needed bodies, or a copied handoff requires recovery. An internal goal continuation or `Stop` retry in retained context does not. Reuse already-read unchanged authority and skill bodies; refresh only material facts that changed. A hash or completion flag cannot reconstruct a body after real context loss.

A direct invocation remains valid when context is retained: check the supplied condition, explain that full recovery is unnecessary, and continue only already-authorized work. Do not manufacture reads or treat the absent positive condition as disabled invocation.

Before real recovery, announce the context loss, preserve harness goal status, and stop source edits, verification, research lanes, and worker waves until the authority is reconstructed. Recovery never grants authority or changes goal status.

## Reload authority in order

1. Read the current attributable human instruction and separate it from synthetic continuation, hook, summary, or worker messages.
2. Use the exact active harness goal path when supplied; do not enumerate or select sibling attachments. Read another attachment only when explicitly designated as historical input. Without an active path, use the latest explicit user designation or goal metadata; ask if two authorities are explicitly active.
3. Read the protected causal section first, then the complete goal through EOF. Follow the user's selected retention model: read exact authoritative references needed for the unfinished slice when that model permits them. Do not substitute references when the user selected a standalone goal.
4. Reload only the contracts and resources required by the actual unfinished phase. A named symbol does not require cold orientation; future testing, quality, documentation, and commit phases do not justify loading their entire portfolio now.
5. Use the summary only to locate artifacts, workers, commands, and evidence; inspect source after the governing causal state is reconstructed.

For multiple instruction files, use [instruction-reads.md](references/instruction-reads.md): batch metadata preflight, then one complete bounded file range per result, with no aggregate-body truncation. Resume at the first unread line and invalidate only files whose content changed. Reuse already-loaded procedure; do not repeatedly open this reference in retained context.

## Reconstruct the unfinished slice

State the objective, selected goal model, exact current phase and owner-level slice, protected chain, last completed effect, and next permitted action. Preserve read/write, command, verification, Git, publication, and delegation boundaries; identify pending decisions, workers, and remaining verification without copying chronology into the goal.

Deduplicate copied history and repeated requirements without multiplying work. If source conflicts with protected architecture, classify it as partial implementation or drift, not a new selected target. Reconcile stale mutable facts only when authorized. If a genuine ambiguity prevents the next effect, stop that effect and repair the contract or request its missing decision; do not pre-decide whole-goal blockage.

Resume the same slice without restarting completed research. Use `$reconcile-live-steering` only for a new attributable human instruction or an actual human instruction delta, including a human's deliberate copy-forward correction. A synthetic message repeating the objective is not new steering. Use `$maintain-living-goal` only when a material goal update or pruning is needed.

Do not report summary- or memory-derived facts as current without the required authoritative recovery.
