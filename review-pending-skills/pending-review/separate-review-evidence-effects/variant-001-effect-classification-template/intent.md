# Effect-classification-template variant

## Concrete intent

Prevent a review request from silently authorizing persistence, helper execution, verification, remediation, Git, activation, or publication.

## Approach

Classify reads, inline analysis, artifacts, collectors, probes, validation, source mutation, Git persistence, activation, and external communication separately and map each to literal authority.

## Preserved nuance

Explicitly requested report files, generated ledgers, validation, and implementation remain required effects. Separation must not become a way to omit intrinsic deliverables.

## Relationships and uncertainty

This overlaps `$filesystem-git-observability` and several audit skills. Review should decide whether this belongs in always-loaded guidance instead of a triggerable skill.
