# Isolated skill evaluation

Use fresh context only when delegation and context isolation are explicitly authorized. A full-history review answers a different question and cannot prove fresh trigger reachability. Otherwise walk through scenarios locally and disclose that no independent evaluator ran.

## Select realistic cases

Include explicit invocation, natural implicit-positive and nearest-negative prompts, mixed-owner work, an unauthorized effect, and a failure-polarity case when relevant. Also preserve the audit's distinctions between package availability, governing disablement, activation, evidence, effect authority, and execution.

For implicit and negative cases, offer the target through the normal discovery surface alongside relevant neighboring owners; do not force invocation or preload its instruction body. For explicit cases, use the actual `$skill-name` request. Supply only the raw artifacts a real task would provide.

Keep case categories, expectations, suspected defects, previous conclusions, desired fixes, and pass criteria out of worker prompts, identifiers, filenames, and fixture contents. Inspect user-supplied prompt and artifact names: a packet builder cannot prove that their semantics are uncontaminated.

## Preserve isolation and authority

- Give each evaluator only its worker packet and declared raw artifacts. Keep the source matrix, evaluator manifest, expectations, and other case outputs inaccessible.
- Use one fresh context and isolated workspace for each case. Record model/version, skill revision, supplied artifacts, actual effects, raw output, and context mode.
- Replace live effects with inert fixtures unless the caller explicitly authorizes the real effect. Designing a test grants no delegation, write, network, or production authority.
- Place generated fixtures and packets under the resolved canonical repository's `.scratchpad/`, unless an explicitly user-selected deliverable destination governs them. Render home paths as `~/...`.

## Judge observations

Score activation as `triggered`, `not-triggered`, or `ambiguous`. Score execution as `contract-satisfied`, `contract-violated`, or `not-exercised`. Cite the raw observation for each judgment and record contamination independently.

A correct answer without the intended skill does not prove activation. A triggered skill can violate its contract. A complete ledger can faithfully record a failed evaluation. A result hash binds evidence to inputs; it does not establish the evaluator's judgment.
