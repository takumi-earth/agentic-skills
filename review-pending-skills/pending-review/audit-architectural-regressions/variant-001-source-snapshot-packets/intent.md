# Source-snapshot verdict-packet variant

## Concrete intent

Produce repeatable architectural-regression assessments that read complete source at named Git checkpoints, embed exact evidence anchors, finish every operation-level disposition, and ask users to approve concrete remediation units rather than approving further investigation.

## Approach

Use a deterministic source collector for worktree and historical blobs, an optional Rust owner-selector call-inventory collector for broad structural-helper families, a structured packet contract, and a validator that rejects missing anchors, undispositioned stable call-site keys, unresolved classification work, incomplete verdict units, and manually hard-wrapped prose. Keep semantic ownership judgments in the reviewed packet rather than encoding one repository's conclusions in the scripts.

## Preserved nuance

A Git diff identifies textual change but does not establish architectural significance. A version-only commit can be irrelevant, a pre-existing defect can still be a current integration regression, and a large whole-item replacement can be the smallest correct seam. The packet must classify each operation from protected ownership, causal boundaries, complete checkpoint source, and preservation evidence.

## Relationships and uncertainty

This candidate overlaps `$audit-rollout-damage`, `$protect-causal-architecture`, `$document-strict-work`, and `$skill-researcher`, but owns a distinct source-history verdict boundary. It does not reconstruct agent traces, alter protected architecture, apply remediation, or enable itself. Review should decide whether the packet contract is sufficiently generic for non-Rust repositories and whether promotion should retain all three scripts as one skill.

## Review questions

- Should a promoted form require a machine-readable operation-disposition manifest in addition to the Markdown packet contract?
- Should promotion retain the source collector, Rust call-inventory collector, and packet validator as one skill package?
- Should future variants add call-inventory extractors for other languages while retaining complete-blob and no-diff classification semantics?
