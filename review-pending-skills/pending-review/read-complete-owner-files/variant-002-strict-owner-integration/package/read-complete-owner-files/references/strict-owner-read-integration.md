# Strict Owner Read Integration

## Activation record

Record:

- exact user wording or disputed owner edge requiring complete reads;
- selected semantic owner files and why each can change the conclusion;
- metadata plan and hash for each file;
- current phase owner;
- whether source changed after the completed read.

## Phase behavior

### Diagnosis and planning

Do not conclude from `rg`, a call-site excerpt, or one method body. Complete the selected model, producer, workflow, façade, and test files that own the disputed behavior.

### Implementation

Reuse the planning read for unchanged files. After editing a file, understand the current complete contents by combining the prior EOF read with the exact owned change; reread the whole file only when concurrent drift or a broad rewrite invalidates that basis.

### Live steering

When the user adds a whole-file requirement, freeze the next conclusion, preserve completed evidence, plan the newly required reads, and resume the same owner-level slice.

### Compaction

Use the exact hashes and next unread ranges. Do not restart completed files or treat a summary as the file body.

## Stop conditions

Stop only the conclusion that depends on an unread or changed owner file. Continue independent authorized work whose evidence contract is already satisfied.
