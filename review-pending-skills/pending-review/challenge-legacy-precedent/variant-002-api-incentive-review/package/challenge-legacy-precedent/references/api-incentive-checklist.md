# Helper API incentive checklist

Ask what the helper makes easy before copying it.

## Inputs

- Does it require one fixed file path when the target may move?
- Does it accept a complete upstream body, fingerprint, hash, or rendered fragment as identity?
- Can a marker or version gate prevent authoritative discovery?
- Does it represent semantic owner, declared scope, load-bearing predicates, and cardinality?

## Outputs

- Does it return raw rendered text as the primary result?
- Can tests query typed owners, candidates, nodes, deltas, paths, and replay?
- Does a boolean collapse absent, ambiguous, incompatible, mixed, and already-applied states?
- Does failure return a partially mutated workspace?

## Defaults

- Does it select the first match or count global text occurrences?
- Does a hint miss stop instead of falling back to the complete semantic query?
- Does it expose string, regex, equality, or snapshot methods as the shortest assertion path?
- Does it preserve unrelated equal-looking nodes by typed identity?

Flag the causal incentive, not merely the presence of a string, path, or boolean. Exact output and explicit whole-content ownership may legitimately use those types in separately owned APIs.
