# Challenge Legacy Precedent

Treat local precedent as implementation evidence, never as authority that silently narrows a protected contract.

## Build the adoption packet

Read [the adoption packet](references/adoption-packet.md) and record:

- the current user or protected invariant;
- the proposed precedent and its actual input/output API;
- which parts are source fact versus inferred policy;
- harmless variations the mechanism must accept;
- states it must reject with typed, non-applying outcomes;
- the target-movement, unrelated-extension, equal-decoy, ambiguity, and real-drift counterfactuals;
- positive evidence and the forbidden-shortcut evidence.

## Compare end to end

Apply the invariant through discovery, mutation, postcondition, tests, and completion evidence. Parser use does not excuse text identity; a passing legacy test does not prove semantic ownership; an existing boolean or first-match helper does not justify collapsing typed states.

## Decide without laundering

Adopt only the compatible portion, narrow or replace the mechanism when its API encodes the wrong contract, or stop for an owner decision. Do not preserve a defect by renaming strings as hashes, markers as semantic owners, or snapshots as accepted shapes.

This review does not authorize source edits, test rewrites, dependency changes, or Git effects.
