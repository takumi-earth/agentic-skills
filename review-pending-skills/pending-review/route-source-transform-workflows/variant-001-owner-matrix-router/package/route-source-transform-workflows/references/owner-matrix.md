# Source transformation owner matrix

| Question | Primary owner | Output |
| --- | --- | --- |
| What user-selected causal architecture, barrier, or authority edge must remain protected? | `$protect-causal-architecture` | Protected current/proposed causal packet |
| Why did the agent choose a shortcut in a named rollout? | `$audit-rollout-damage` | Evidence-backed reasoning and effect timeline |
| What does current source or a checkpoint actually contain? | `$audit-architectural-regressions` | Source inventory and divergence packet |
| How should one production parsed-source transform discover, classify, rewrite, and replay? | `$design-semantic-source-transforms` | Typed transformation contract |
| How should adaptive behavior, owner identity, negative states, movement, and replay be tested? | `$test-adaptive-source-transforms` | Typed behavioral and metamorphic test design |
| After tests are removed or broadly rewritten, is every prior behavior still protected? | `$verify-test-parity` | Old-to-new behavior parity ledger |

## Handoff rules

- Give every artifact one primary owner.
- Pass cited evidence or declared contracts across owners; do not transfer authority.
- Let current source establish facts, while protected user decisions establish target architecture.
- Use adaptive-test design for the new assertion surface and parity for historical behavior coverage; neither substitutes for the other.
- Preserve current phase authority before any read, write, command, validation, Git, or external effect.
