# Route Source Transform Workflows

Assign each question to one semantic owner and keep its evidence there.

## Select owners

Read [the owner matrix](references/owner-matrix.md). Route by the question being answered:

- protect a user-selected architecture, authority edge, barrier, or mutation sequence with `$protect-causal-architecture`;
- reconstruct why an agent chose a shortcut from rollout evidence with `$audit-rollout-damage`;
- inventory what source and checkpoints currently contain with `$audit-architectural-regressions`;
- design one location-independent parsed-source transformation with `$design-semantic-source-transforms`;
- design typed, metamorphic, product-owner evidence with `$test-adaptive-source-transforms`;
- prove behavioral parity after removing or broadly rewriting tests with `$verify-test-parity`.

## Prevent circular handoffs

Name a primary owner for each output and use neighboring skills only for their distinct inputs. Current-source inventory does not decide protected architecture. Historical reasoning does not define production design. Adaptive-test design does not certify parity for removed coverage, and parity analysis does not own the new harness architecture.

## Preserve phase authority

Loading or routing to a skill does not authorize its commands, writes, validation, commits, or external effects. Follow the current user instruction and repository phase owners. This router produces a responsibility map only; it does not mutate code or evidence.
