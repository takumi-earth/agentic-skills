# Terminal status-checklist variant

## Concrete intent

Reconcile stale mutable status after authorized work reaches a terminal applied state without erasing protected decisions, chronology, or deliberately unrun verification.

## Approach

Use a proportional post-application checklist: map each current unit to evidence, replace operative stale prose, retain former states only as attributable history, prune duplicated applied snapshots, and run one focused contradiction scan.

## Preserved nuance

Applied remediation does not prove repository correctness or complete a broader product goal. Harness completion remains a separate user-owned transition.

## Relationships and uncertainty

This overlaps `$maintain-living-goal` and `$document-strict-work`. Review should decide whether it is better as a terminal phase of the existing living-goal owner.
