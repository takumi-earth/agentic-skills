# Evidence-manifest variant

## Concrete intent

Produce deterministic qualitative damage assessments from agent rollout traces without embedding one incident's conclusions, file names, ordinals, statistics, or remediation choices in executable code.

## Approach

Separate the workflow into generic trace indexing, edit-candidate discovery, an evidence-hashed incident manifest, generic measurement expressions, deterministic representative selection, Markdown/JSON rendering, and two-run reproducibility checks. Treat qualitative classifications and remediation judgments as cited manifest data rather than program logic.

## Preserved nuance

A landed repository edit is not inert. Only a non-applying remediation candidate or report plan is inert. Exact byte recovery confidence is independent from semantic severity and independent from authorization to apply a repair. Mixed-authority goal and test-ledger edits require statement-level adjudication even when a whole-file inverse is mechanically available.

## Relationships and uncertainty

This candidate overlaps `$protect-causal-architecture`, `$verify-test-parity`, and `$skill-researcher`, but owns a distinct forensic report boundary: reconstructing agent effects and rendering a review artifact without deciding protected authority or applying remediation. Review should decide whether the generic measurement vocabulary is sufficient for future rollouts or needs additional aggregation operations.

## Review questions

- Should a promoted form remain read-only, or should separately authorized inverse-plan generation become a sibling skill?
- Should future variants add harness-specific adapters while retaining the same normalized evidence and report contracts?
