# Test Adaptive Source Transforms

Prove the semantic relationship the transformation promises. Never use rendered source as a proxy for structural correctness.

## Establish the oracle boundary

Apply this rule to production tests, helpers, fixtures, snapshots, custom matchers, and generated expectations:

> Rendered parsed source is not a correctness oracle for a structural transformation.

Reject substring, regex, prefix or suffix, raw rendered equality, snapshots, copied production bodies, and parse-then-text laundering when they are used to prove target selection, mutation ownership, preservation, drift handling, or idempotency.

Do not reduce this contract to a ban on `.contains(...)`. A method-name grep both misses equivalent wrappers and rejects legitimate string contracts.

Exact text assertions are appropriate only when text or bytes are themselves the documented contract, such as wire fields, CLI output, stable diagnostic codes, generated bytes, or intentionally repository-owned generated source. Keep those tests in an explicitly named rendering-contract layer.

## Build five evidence layers

Keep these responsibilities separate:

1. **Primitive transformation tests:** prove a minimal, version-neutral syntax shape produces the typed semantic delta and postcondition.
2. **Inventory and wiring tests:** prove a stable transformation ID is registered with the correct owner, scope, query, rewrite, cardinality, and disposition.
3. **Discovery and metamorphic tests:** prove irrelevant variation, relocation, decoys, ambiguity, drift, post-state recognition, and replay behavior.
4. **Product-owner behavior tests:** exercise authentication, streaming, cancellation, schema, lifecycle, diagnostics, or other real behavior through its actual owner.
5. **Rendering-contract tests:** assert exact text only where exact text is the external contract.

Version-specific load-bearing structural predicates or bounded syntax variants, when genuinely required, belong once in the production transformation declaration. Complete upstream-owned bodies, full-item token signatures, and equivalent snapshots belong neither in the declaration nor in test fixtures.

## Make typed assertions the easiest path

Return a typed result from structural helpers, equivalent to:

```rust
struct AppliedSourceTransformation {
    outcome: TransformationOutcome,
    syntax: ParsedWorkspace,
    delta: SemanticDelta,
    changed_files: Vec<WorkspacePath>,
}
```

Do not expose unrestricted rendered source from this result. Avoid `Deref<Target = str>`, `AsRef<str>`, `Display` as an assertion surface, or a convenience `rendered_source()` method in structural tests.

Treat `ParsedWorkspace` as an opaque structural-query facade. Do not expose raw source bytes, unrestricted parser nodes, token streams, debug or serialized renderings, hashes, or other escape hatches that can be laundered into a textual oracle.

Provide typed query helpers for declarations, implementations, calls, arguments, fields, arms, paths, ownership IDs, candidates, and deltas. Assert facts such as:

- the selected entity has the intended semantic identity;
- the intended child node changed once inside that owner;
- an equal-looking node in an unrelated owner is structurally unchanged;
- unrelated fields, branches, statements, attributes, and siblings are preserved;
- cardinality and the typed outcome variant are correct;
- the discovered changed path follows the moved target;
- replay has an empty semantic delta.

An exact count is valid when it counts typed query results in the selected owner and cardinality is part of the contract. A count over rendered source is not.

## Run the adaptive matrix

Read [the metamorphic and mutation matrix](references/metamorphic-matrix.md) whenever adding, porting, or broadly reviewing an adaptive transformation suite.

For each transformation, cover at least:

- trivia and formatter changes;
- line shifts and item reordering;
- file or permitted-module movement;
- unrelated structural extension;
- equal-looking decoys and a stale path-local near match;
- two genuine candidates;
- real load-bearing drift;
- dependency, lockfile, or package-version changes with unchanged relevant source semantics;
- recognized post-state and replay.

Vary the fixture without changing the transformation or test declaration. If every variation requires a new expected source body, the suite is snapshotting upstream rather than proving adaptation.

Use this mutation check:

> Swap the intended node with an unrelated equal-looking node. If the positive test still passes, the oracle is inadequate.

## Prove actual product behavior

Do not use marker functions or invented calls whose names claim that streaming, cancellation, authentication, OAuth, schema, or lifecycle behavior was preserved. Exercise the real product owner, observable effects, failure order, cancellation path, emitted protocol value, or typed state transition.

When a source transformation only wires a product-owned hook, test the small semantic wiring in the transformation suite and the substantive behavior in the product owner's suite.

## Harden mechanically by construction

- Keep rendering inside parser or diagnostic adapters, away from structural assertion APIs.
- Reject parse-then-text helpers and custom wrappers that launder rendered nodes into ordinary strings.
- If an automated gate is required, use type-aware or dataflow-aware enforcement scoped to values derived from parsed or transformed source. Do not add a repository-wide string-method grep.
- Use compile-fail or API-shape tests where practical to prove structural results cannot reach raw-string assertion helpers.
- Detect large trivia-free fixture overlap with upstream production items as a review signal. Do not reuse that overlap signature as the transformation's applicability mechanism.
- Assert typed diagnostics, stable codes, candidates, paths, cardinality, and structured fields. Treat English wording as exact only when it is public API.

## Replace brittle tests without losing behavior

Use `$verify-test-parity` before deleting, consolidating, or broadly rewriting existing tests. `$verify-test-parity` owns the immutable baseline, contract decomposition, disposition ledger, and closure decision; this skill owns the structural oracle and adaptive replacement design.

For each brittle test:

1. Decompose every observable contract it claims to protect.
2. Identify the real production or product owner of each live contract.
3. Add equal-or-stronger typed or behavioral evidence at that owner.
4. Remove invalid assertion mechanics only after every claimed live contract has replacement evidence; do not record the mechanics as intentionally retired product behavior.
5. Preserve legitimate rendering contracts in their separate layer.

Do not count a newly written but unexecuted test as verification evidence. Test source is implementation until the authorized focused and canonical gates run successfully.

## Stop on an unprovable oracle

Stop and report the missing owner or contract when:

- the only proposed assertion surface is rendered upstream source;
- a fixture must copy a complete upstream-owned implementation;
- preservation is represented only by a marker name;
- target and decoy ownership cannot be distinguished through typed queries;
- the product behavior has no executable owner-level observation;
- an exact-text exception lacks a documented external text contract.

Do not weaken the transformation promise to fit an easy fixture or a locally green test.
